# WebKVM v0.1.13

Feature release: maintenance-safe node drain, browser push notifications and
optional OIDC/SSO login, plus a full i18n cleanup and a more deterministic CI.

## Añadido / Added

- **Node drain and evacuation** (admin): mark a libvirt node as draining,
  block new placements and destinations, inspect a per-VM plan, and migrate
  migratable instances to another node. Pacemaker-managed, Incus,
  GPU-passthrough and stale entries are skipped with a reason. The plan also
  reports offline VMs that require shared storage.
- **Browser push notifications** (opt-in per user, Account page): VAPID
  subscriptions, a service worker, a test notification and alerts when a
  background job finishes. No subscription means no notifications.
- **OIDC/SSO login** (optional, environment-configured): authorization-code
  flow with PKCE, signed state/nonce, ID-token signature/issuer/audience
  validation, role mapping, optional auto-provisioning and optional local
  login lockdown. `admin` keeps a break-glass local login. Existing local
  accounts are never attached to an SSO subject automatically.
- **i18n regression gate**: `scripts/check-hardcoded-es.mjs` runs in CI and
  fails new hardcoded Spanish UI literals.

## Corregido / Fixed

- **CI flakiness**: the federation parallelism test waits until both remote
  calls start instead of asserting a 700ms deadline; the handshake-cooldown
  flood uses a 30s window so a slow runner cannot expire it mid-test. CI now
  annotates failing tests and the log tail when no test marker matches.
- **Spanish UI leftovers**: VM audio labels, deployment tasks, terminal
  shortcuts, RAID/disk initialization, shared-folder mounts, batch clone,
  AppStore script comments, network labels and other literals now use `t()`
  in `en`, `es` and `ca`.
- **Backend fallbacks**: auth, quota, media-protection, host-update progress
  and the embedded VNC keyboard helper now return English text; the SPA
  localizes by stable codes.
- **CodeQL hygiene**: the i18n scanner uses line-based comment/code masking
  instead of regex HTML filtering, clearing the four tooling alerts; the
  command-runner and Incus trust-on-first-use findings are documented and
  dismissed as intentional.

## Cambiado / Changed

- **Default bind address**: fresh installs listen on `0.0.0.0` so the UI is
  reachable on the LAN without editing `config.json`. If TLS is off, the
  backend falls back to `127.0.0.1` unless `WEBKVM_ALLOW_INSECURE_HTTP=1` is
  set. Existing installs keep their persisted `server.bind_addr`. Behind a
  TLS reverse proxy, use `127.0.0.1`.
- **AUR**: `webkvm-bin` is an unofficial third-party package. The in-repo
  `packaging/arch/PKGBUILD` is a local-build reference; WebKVM does not
  publish or endorse the AUR package.
- **Dependencies**: `github.com/SherClockHolmes/webpush-go v1.4.0`;
  `github.com/zitadel/oidc/v3` is now a direct dependency.

## Security notes

- OIDC is off unless `WEBKVM_OIDC_ENABLED=1` and the issuer/client/secret/
  redirect URL are configured. The client secret is read from the
  environment and never returned by the API.
- OIDC uses PKCE, a signed state cookie and a nonce check. Local users are
  not silently linked by username or email.
- Web Push is opt-in per browser/user. The VAPID private key is stored in
  `webpush.json` (0600) under the data directory.
- Drain refuses to start on Incus nodes (use the Incus cluster evacuation)
  and skips VMs that cannot be migrated safely instead of forcing them.

## Updating

Native installs: **Status → Update**. Systems on `0.1.12`, `0.1.12-fix01`,
`0.1.12-fix02` or earlier are offered this release. If the button is not
shown, run once:

```bash
sudo webkvm-update
```

The updater downloads `webkvm-0.1.13-linux_amd64`, verifies `SHA256SUMS`,
keeps `webkvm.previous` and health-checks the result. Docker installs pull
the new image instead.

## Checksums

See `SHA256SUMS` in the release assets. It covers the tarball, raw binaries,
`.deb` and `.rpm` under the exact uploaded filenames.
