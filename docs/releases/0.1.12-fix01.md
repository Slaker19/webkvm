# WebKVM v0.1.12-fix01

Security and packaging follow-up to v0.1.12. The application behaviour is the
same; this release rebuilds with the fixed Go toolchain and updates the
updater and security automation.

## Corregido / Fixed

- **Go 1.26.11**: rebuilds with the fix for `GO-2026-6859` (HTTP/1 server crash
  via a `MaxBytesReader` header race). The v0.1.12 release binary was already
  built with Go 1.26.11; `go.mod` and CI now require it explicitly.
- **`golang.org/x/crypto`**: updated to
  `v0.58.1-0.20261009181718-2f1f834330b2`, clearing `GO-2026-5932` (unmaintained
  openpgp). The affected package was not called by WebKVM.
- **Updater**: `isNewer` now understands the `-fixNN` suffix, so a system on
  `0.1.12` is offered `0.1.12-fix01` correctly. (Older 0.1.12 binaries need one
  manual `sudo webkvm-update`; see below.)
- **CI/CD**: release jobs pin Go 1.26.11; CodeQL is enabled for Go and
  JavaScript/TypeScript.

## Añadido / Added

- **CodeQL workflow** for Go and JavaScript/TypeScript, with manual Go build
  and SARIF upload to GitHub code scanning.
- **Release notes file** published directly in the GitHub release.
- **Test coverage** for the `-fixNN` updater comparison.

## Base v0.1.12: corregido / fixed

- External snapshot deletion/revert with the VM off on Debian/Ubuntu:
  libvirt's AppArmor `deny ... w` rule is bypassed by a configurable
  per-domain AppArmor label; disk-chain ownership is set to QEMU.
- Existing domains are migrated lazily on the next start, revert or snapshot
  delete, so an in-place UI update needs no XML edit.
- Missing VMs, pools, volumes, ISOs, snapshots, PCI/USB devices, shared
  folders and templates return 404 instead of 500.
- Network interface PATCH accepts URL-encoded MAC addresses.
- Deleting a paused or suspended VM destroys QEMU before undefining it.
- Hardcoded Spanish strings were removed from AppStore, ImageHub, MultiView,
  VmList, CronPicker and the VM disk card (the wider i18n cleanup is tracked
  in issue #11).
- Host upgrades no longer fail with a read-only `/etc`; upgrade jobs expose
  stable error codes.

## Base v0.1.12: añadido / added

- Multi-node cluster: federated VM listing, remote create/read/delete,
  migration, managed SSH and node inventory.
- In-app updater with release checksum verification, `webkvm.previous`
  rollback and source/release mode detection.
- `WEBKVM_DISABLE_APPARMOR` (default `1` on AppArmor hosts; SELinux unaffected).
- HA/cluster module and runbooks, release checklist, and the updated
  documentation set.

## Updating

Native installs: **Status → Update**. From `0.1.11` or earlier the updater
offers this fix. Systems already on the old `0.1.12` binary do not see the
button (its comparison ignores the `-fix` suffix); run:

```bash
sudo webkvm-update
```

The updater downloads `webkvm-0.1.12-fix01-linux_amd64`, verifies
`SHA256SUMS`, keeps `webkvm.previous` and health-checks the result. Docker
installs pull the new image instead.
