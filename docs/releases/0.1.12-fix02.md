# WebKVM v0.1.12-fix02

Packaging and maintenance follow-up to v0.1.12-fix01. The application
behaviour is unchanged; this release fixes native package naming and version
ordering, updates a Go dependency, and localizes the specific strings called
out in issue #11.

## Corregido / Fixed

- **`.deb` checksum verification**: the Debian package is now uploaded as
  `webkvm_0.1.12.fix02_amd64.deb` and its `SHA256SUMS` entry matches the asset
  name. GitHub rewrites `~` to `.` during upload, which made `sha256sum -c`
  fail for v0.1.12-fix01.
- **Native package ordering**: Debian builds `0.1.12.fix02` and RPM builds
  `0.1.12-1.fix02`, so `apt`/`dnf` treat this release as an upgrade over
  `0.1.12`. The previous `0.1.12~fix01` / `0.1.12-0.fix01` versions sorted
  below the base release.
- **i18n leftovers from issue #11**: the VM audio-model labels and the app
  deployment task text now use `t()`; wrong-password detection uses the stable
  `invalid_password` error code instead of a Spanish string. The wider sweep
  of ~190 literals remains tracked in issue #11.
- **Go dependencies**: `go.opentelemetry.io/otel*` updated to `v1.47.0`
  (Dependabot PR #13). No security advisory is involved.

## Añadido / Added

- **Release notes file** `docs/releases/0.1.12-fix02.md`, published directly in
  the GitHub release.

## Base v0.1.12: corregido / fixed

- External snapshot deletion/revert with the VM off on Debian/Ubuntu:
  libvirt's AppArmor `deny ... w` rule is bypassed by a configurable
  per-domain AppArmor label; disk-chain ownership is set to QEMU.
- Existing domains are migrated lazily on the next start, revert or snapshot
  delete, so an in-place UI update needs no XML edit.
- Missing VMs, pools, volumes, ISOs, snapshots, PCI/USB devices, shared
  folders and templates return 404 instead of 500.
- Network interface PATCH accepts URL-encoded MAC addresses.
- Deleting a paused or suspended VM destroys QEMU before undefining it.
- Hardcoded Spanish strings were removed from AppStore, ImageHub, MultiView,
  VmList, CronPicker and the VM disk card.
- Host upgrades no longer fail with a read-only `/etc`; upgrade jobs expose
  stable error codes.

## Base v0.1.12: añadido / added

- Multi-node cluster: federated VM listing, remote create/read/delete,
  migration, managed SSH and node inventory.
- In-app updater with release checksum verification, `webkvm.previous`
  rollback and source/release mode detection.
- `WEBKVM_DISABLE_APPARMOR` (default `1` on AppArmor hosts; SELinux unaffected).
- HA/cluster module and runbooks, release checklist, and the updated
  documentation set.

## Updating

Native installs: **Status → Update**. Systems on `0.1.12-fix01` or `0.1.11`
and earlier see this release. Systems still on the original `0.1.12` binary
ignore the `-fix` suffix and do not see the button; run once:

```bash
sudo webkvm-update
```

The updater downloads `webkvm-0.1.12-fix02-linux_amd64`, verifies
`SHA256SUMS`, keeps `webkvm.previous` and health-checks the result. Docker
installs pull the new image instead.

## Checksums

See `SHA256SUMS` in the release assets. It now covers the tarball, raw
binaries, `.deb` and `.rpm` under the exact uploaded filenames.
