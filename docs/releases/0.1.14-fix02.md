# WebKVM v0.1.14-fix02

Hotfix on top of v0.1.14-fix01.

## Fixed: OPNsense / IPFire / FreeBSD / OpenWrt deploys never finished

The deploy job's sanity guard compared the **decompressed** image size
against the catalog's `SizeBytes`, which is the **compressed** download
size. bz2/xz/gz routinely compress 3–6x, so every healthy download of
these appliances was rejected at the finish line:

```
downloaded size (2642520064) far exceeds expected (493886640)   # OPNsense
```

- The compressed archive is now validated right after the download
  (while the file is still on disk, before it is removed for
  decompression), with a 2x margin over the catalog's compressed size.
- After decompression only the minimum-size and format-magic checks
  remain — no compressed-vs-decompressed comparison exists anymore.
- Catalog compressed sizes corrected with actually-measured values:
  flatcar 592,617,837 (was 450,000,000), freebsd-14 653,136,048 (was
  400,000,000), ipfire 533,996,648 (was 600,000,000). Existing installs
  whose catalogs were already seeded self-heal on upgrade (layout v3).

Affected entries that previously hard-failed: opnsense, ipfire,
freebsd-14, openwrt-25.12. pfsense-ce, haos and flatcar happened to
pass by margin.

## Upgrading

Native installs update from `/#/status`; Docker pulls
`slaker1908/webkvm:latest`. After upgrading, re-run the deploy of the
appliance that failed — no data cleanup is needed (the failed jobs
already removed their partial downloads).
